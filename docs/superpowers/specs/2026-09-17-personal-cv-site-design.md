# Personal CV / portfolio site — design

## Purpose

A public personal site combining a CV-style landing page and a portfolio of
technical projects, to share as a link in job applications and with
recruiters (complements the PDF CV generated by Diggo, doesn't replace it).

## Goals

- Give recruiters a fast, low-friction overview (summary, current role,
  contact) without opening a PDF.
- Showcase technical projects in more depth than a CV allows (diggo,
  rag-lab, Kaggle Watson, Restaurant Analytics, merged OSS contributions).
- Free to host, near-zero maintenance overhead once live.

## Non-goals

- Not a synced mirror of `diggo/config/cv.yaml`. Content is written once for
  the web (different tone/format than a CV PDF) and maintained independently
  — no regeneration pipeline.
- No backend, no contact form with server-side processing, no CMS.
- No custom domain for now (`github.io` subdomain is enough to start).

## Architecture

Jekyll site, native to GitHub Pages — zero dependency to install, zero CI to
write; GitHub Pages builds and deploys automatically on push to `main`.

Repo: `St4r4x.github.io` (root user site, not a project subpage), personal
GitHub account (`github.com-personal` SSH host per convention).

```
_config.yml
_layouts/default.html      # shared shell: <head>, nav, footer
_includes/nav.html         # nav + language toggle
_includes/footer.html
fr/index.md   fr/cv.md   fr/projects.md
en/index.md   en/cv.md   en/projects.md
assets/css/style.css
assets/img/...
```

No JS framework, no build tool beyond Jekyll itself.

## Pages

Content rewritten from `diggo/config/cv.yaml` for the web (not copy-pasted):

- **Home** (`/fr/`, `/en/`): short hook, condensed professional summary,
  current role (Missia), links to CV and Projects pages, contact.
- **CV** (`/fr/cv.html`, `/en/cv.html`): full experience, skills by
  category, education, certifications — web-formatted, not a PDF mirror.
- **Projects** (`/fr/projects.html`, `/en/projects.html`): diggo, rag-lab,
  Kaggle Watson, Restaurant Analytics, OSS contributions (sacrebleu,
  pyserini) — more context and a GitHub link per project than the CV
  affords.

## Language handling

Each page's front matter carries `lang: fr|en` and `alt_url: <path>` (the
same page in the other language). `_includes/nav.html` reads these two
values to render the language toggle link. No dynamic routing, no
JS-driven show/hide — plain static pages under `/fr/` and `/en/`.

## Deployment

GitHub Pages, "Deploy from branch" on `main`. Root user site → served at
`https://st4r4x.github.io/`. No `CNAME` file (no custom domain yet); can be
added later without restructuring.

## Testing / verification

No automated tests — purely static content, no logic to break. Visual
check locally via `bundle exec jekyll serve` before pushing, and a check of
the live GitHub Pages URL after the first deploy.

## Open questions

None blocking. Custom domain is an explicit non-goal for v1, revisit later
if desired.
